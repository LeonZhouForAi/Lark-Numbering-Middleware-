# v0.2.4 正确性与安全加固设计

## 背景

v0.2.3 已完成飞书长连接、DeepSeek 混合切片、SQLite 检索和来源隐藏，但综合审查发现 4 类适合立即热修的问题：本地回退切片可能丢失正文、长连接模式仍暴露可放行的 Webhook、多个进程共享 SQLite 时缺少并发参数，以及语义切片降级没有可诊断日志。

用户已确认三个规划版本都要实施，并先完成 v0.2.4，完成后提交 Git。本版只提交代码，不直接部署 Ubuntu 生产环境。

## 方案比较

### 方案 A：最小热修（采用）

- 修复本地切片覆盖率。
- Webhook 在没有 Encrypt Key 时拒绝签名，Docker 端口默认只绑定本机。
- SQLite 启用 WAL、30 秒 busy timeout 和 NORMAL 同步级别。
- 启用现有 `LOG_LEVEL`，记录语义切片回退和长连接处理异常。
- 将项目版本升级到 0.2.4，切片策略升级到 `hybrid-v3`。

优点是变更小、可独立验证、适合热修。缺点是暂不解决飞书删除文档清理、API 重试、完整监控和检索质量评估。

### 方案 B：一次完成全部可靠性改造

在方案 A 基础上同时增加文档生命周期、API 重试、自动备份、金标评估和结构化回答。优点是完整，缺点是范围过大，无法作为低风险热修，回归和部署风险更高。

### 方案 C：只修复切片丢字

改动最少，但会保留已确认的 Webhook 暴露、SQLite 锁竞争和静默降级风险，不满足 v0.2.4 的加固目标。

## 设计

### 1. 本地切片覆盖率

保留现有段落优先策略和 `_split_long_unit`。在合并下一个单元时，不再对 `carry + unit` 直接截断。程序先保证完整保留当前 `unit`，再根据剩余容量缩短或取消来自上一片的 overlap。

不变量：规范化后的所有非空白原文字符必须至少出现在一个切片中；每个切片长度不得超过 `max_chars`。

### 2. Webhook 与端口边界

- `verify_signature` 在 Encrypt Key 为空时返回 `False`。
- 长连接不依赖 Webhook 签名，因此该改动不影响 `rag-events`。
- Compose 使用 `RAG_BIND_HOST`，默认值为 `127.0.0.1`，仅允许服务器本机访问 8010。
- 确实需要 Webhook 时，运维人员必须显式设置可访问的绑定地址和非空 Encrypt Key。

### 3. SQLite 并发保护

每个 `IndexStore` 连接使用 30 秒连接超时，并执行：

```sql
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 30000;
PRAGMA synchronous = NORMAL;
PRAGMA foreign_keys = ON;
```

本版继续保持每个进程独立连接，不引入连接池或数据库迁移。

### 4. 可诊断日志

新增小型日志配置函数，统一使用现有 `LOG_LEVEL`。日志包含时间、级别、模块和消息，不记录文档正文、API Key、App Secret 或服务器密码。

需要记录：

- Wiki 和本地文档语义切片回退：记录 `source_id` 与异常类型。
- 长连接单条消息处理失败：记录异常类型，防止异常从回调函数逸出。
- 同步完成统计：记录 `nodes_seen`、`indexed` 和 `skipped`。

外部告警通道、Token 成本统计和 API 重试放入 v0.3.0，不在热修中新增依赖。

### 5. 版本与缓存

- 项目版本：`0.2.4`。
- 切片策略：`hybrid-v3`。
- README、`.env.example` 和 CHANGELOG 同步更新。
- 部署 v0.2.4 时必须修改生产 `.env` 的策略版本并全量同步，确保旧的本地回退切片被重新计算。

## 测试与验收

1. 新增回归测试，使用 100 个唯一字符复现旧实现丢字，修复后原文字符覆盖率为 100%。
2. 新增签名测试，空 Encrypt Key 必须拒绝。
3. 新增 SQLite PRAGMA 测试，确认 WAL、busy timeout 和 NORMAL。
4. 新增日志测试，语义规划器失败时必须留下不含正文和密钥的 WARNING。
5. 运行完整 pytest，现有 44 项测试和新增测试全部通过。
6. 运行 `git diff --check` 和密钥扫描，提交中不得出现生产凭据。

## 非目标

- 不在本版实现飞书已删除文档清理。
- 不在本版加入向量数据库、Embedding 或重排序。
- 不在本版加入部门权限过滤。
- 不在本版部署生产环境或轮换凭据。
- 不在本版增加外部告警平台、API 重试或成本仪表板。

## 回滚

代码回滚到 v0.2.3 即可。SQLite WAL 是兼容模式，不修改业务表结构。`hybrid-v3` 只影响缓存签名，不改变已有数据库字段。
