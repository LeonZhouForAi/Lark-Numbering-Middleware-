# v0.5.0 高频问答索引设计

## 1. 背景

“瀚邦为知识库助手”当前对每个有效问题都执行本地检索和 DeepSeek 生成。对于反复出现的制度问题，这会重复消耗模型额度，也会增加响应时间。

本版本增加高频问答索引（Hot FAQ Cache）。系统自动识别同一意图的不同问法，在最近 15 天内累计达到 3 次后，保存经过安全检查的标准答案并自动启用。后续命中时仍执行轻量本地检索，但不再调用 DeepSeek。

## 2. 已确认决策

- 高频窗口：最近 15 天。
- 自动启用阈值：同一意图累计 3 次。
- 答案来源：只允许来自当前 RAG 流程和当前知识库资料。
- 同义问法：采用本地语义归一化，不引入向量数据库。
- 自动更新：资料实际新增、修改或删除后，旧标准答案立即失效；下一次相关提问重新执行 RAG 并自动覆盖。
- 权限范围：当前所有员工可读取全部知识库，FAQ 为全局共享；仍保留 `RetrievalScope` 兼容边界。
- 发布版本：v0.5.0。

## 3. 目标

1. 高频问题命中后不调用 DeepSeek，缩短回复时间并降低模型费用。
2. 将“供应商开发流程是什么”和“新供应商怎么导入”等同义表达归入同一标准问题。
3. 保证标准答案随知识库资料更新而失效和重建。
4. 不缓存资料不足、错误、危险内容、带来源信息或包含个人标识的问题/答案。
5. 不保存员工姓名、飞书用户 ID 或其他身份信息。
6. 提供可审计的热门问题、命中率、节省请求数和失效数量统计。

## 4. 非目标

- 不引入向量数据库、Embedding API 或新的外部模型。
- 不建设人工审核后台或可视化管理页面。
- 不绕过现有限流、权限边界和输出安全检查。
- 不把历史对话或员工身份写入 FAQ 数据库。
- 不将 FAQ 答案作为知识库原文反向写回飞书。

## 5. 总体架构

新增独立的 `FaqService`，负责问题归一化、意图归组、频率累计、缓存读取和失效判断。`RagService` 继续负责文档检索、DeepSeek 生成和输出安全检查。

```text
员工问题
  ↓
现有限流与消息去重
  ↓
本地文档检索
  ↓
FaqService 计算问题特征和命中文档特征
  ├─ 有效 FAQ：直接返回标准答案，不调用 DeepSeek
  └─ 未命中/已失效：执行正常 RAG
                         ↓
                    安全检查通过
                         ↓
                    记录观察次数
                         ↓
             15 天内达到 3 次后自动启用
```

FAQ 命中仍执行本地 SQLite 检索，用于确认当前问题和标准问题命中同一组核心资料。本地检索不产生模型费用。

文档索引采用“准备后原子提交”策略：下载、解析、OCR 和语义切片阶段只在内存中形成待写入文档，不修改 SQLite；所有文件准备成功后，才在一个 SQLite 事务内写入全部文档、删除失效文档并递增知识库版本。这样任一步失败时，文档内容与 FAQ 版本都会保持旧状态。

RAG 在本次本地检索完成时固定 `knowledge_revision`，并将其随本次生成过程传递。缓存直发前的计数事务必须再次确认 FAQ 条目版本和当前知识库版本一致；若资料在检索或模型生成期间更新，本次旧资料答案不得直发或写入当前版本 FAQ。

若生成结束时检索快照版本已变化，系统必须丢弃旧资料答案并以新版本重新检索、重新生成一次。若重试期间版本再次变化，返回固定更新中提示，不发送任一旧资料答案。

## 6. 问题归一化与同义匹配

### 6.1 文本归一化

沿用现有 NFKC、大小写折叠、中文二元词和问题外壳清理能力，并增加受控同义词映射，例如：

- 开发、导入、准入 → 准入
- 怎么走、怎么办、如何办理、流程是什么 → 流程
- 报销、费用报销 → 报销

同义词表只用于本地匹配，不修改员工原问题，也不参与最终回答生成。

### 6.2 文档特征

本地检索后，从高相关结果中提取排序稳定的 `source_id` 集合，并计算 `source_signature`。该集合同时保存为 `source_ids_json`，不能只保留哈希；否则服务重启后无法计算来源重叠率。FAQ 查询先读取同一 `scope_key` 下的候选别名，再在服务层计算文本与来源相似度。只有同时满足以下条件才能直接复用答案：

1. 标准问题或已观察别名与当前问题达到高相似度；
2. 当前问题与 FAQ 命中相同的核心文档特征；
3. FAQ 记录的知识库版本仍是当前版本；
4. FAQ 状态为启用。

任一条件不满足时必须回退普通 RAG，不能为了提高命中率降低正确性。

### 6.3 稳定意图键

`intent_key` 只由归一化后的语义核心词计算哈希，不包含权限范围或 `source_signature`。权限范围单独保存为 `scope_key`。原始问题保存在别名表中，用于后续高相似问法匹配；两个键都不包含员工身份。

`intent_key` 必须在资料更新前后保持稳定，`source_signature` 则用于校验当前问题是否仍命中同一类核心资料。若同一 `intent_key` 在观察期内反复出现不同且互不相容的文档特征，系统不得自动晋级该问题，而应继续走普通 RAG。这样既允许资料更新后原位刷新答案，又能阻止“审批流程”等泛化问法错误共用答案。

## 7. 数据模型

### 7.1 `knowledge_state`

单行保存当前知识库版本：

| 字段 | 类型 | 说明 |
|---|---|---|
| singleton_id | INTEGER | 固定为 1 |
| revision | INTEGER | 单调递增的知识库版本 |
| updated_at | REAL | 最近实际变更时间 |

只有完整成功的同步或本地索引确认文档集合/校验和发生变化时才递增 `revision`。分页失败、下载失败、解析失败或部分同步不得递增版本，也不得将已准备但尚未完整成功的文档写入数据库。

### 7.2 `faq_entries`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT | UUID 主键 |
| intent_key | TEXT | 稳定的标准意图键 |
| scope_key | TEXT | 权限范围隔离键 |
| canonical_question | TEXT | 首个代表性问题 |
| answer | TEXT | 已通过安全检查的标准答案 |
| source_signature | TEXT | 核心文档特征哈希 |
| source_ids_json | TEXT | 用于来源重叠校验的排序 `source_id` JSON 数组 |
| knowledge_revision | INTEGER | 生成答案时的知识库版本 |
| state | TEXT | `enabled` 或 `stale` |
| direct_hits | INTEGER | 直接回复累计次数 |
| created_at | REAL | 创建时间 |
| updated_at | REAL | 最近生成时间 |
| last_hit_at | REAL | 最近直接命中时间 |

`(scope_key, intent_key)` 设置复合唯一约束，保证同一权限范围内每个稳定意图只有一条当前 FAQ。

### 7.3 `faq_aliases`

| 字段 | 类型 | 说明 |
|---|---|---|
| faq_id | TEXT | 关联 FAQ |
| normalized_question | TEXT | 归一化后的同义问法 |
| search_text | TEXT | 本地预分词文本 |
| first_seen_at | REAL | 首次出现时间 |
| last_seen_at | REAL | 最近出现时间 |
| total_seen | INTEGER | 累计观察次数 |

### 7.4 `faq_observation_daily`

按自然日保存匿名频次桶：

| 字段 | 类型 | 说明 |
|---|---|---|
| intent_key | TEXT | 意图键 |
| scope_key | TEXT | 权限范围隔离键 |
| day | TEXT | `YYYY-MM-DD` |
| count | INTEGER | 当日出现次数 |
| normalized_question | TEXT | 代表性归一化问法 |
| source_signature | TEXT | 当时的文档特征 |
| knowledge_revision | INTEGER | 当时的知识库版本 |
| latest_safe_answer | TEXT | 最近一次安全 RAG 答案 |

系统按最近 15 个自然日求和。过期观察桶可定期清理。

观察桶以 `(scope_key, intent_key, normalized_question, source_signature, knowledge_revision, day)` 为复合唯一键。同一稳定意图的不同归一化问法分别保留日频次，但晋级时按同一范围、意图、资料特征和版本聚合所有别名的最近 15 天计数。达到阈值后，所有已观察到的归一化问法都写入别名表，确保触发晋级的问法和此前问法都能命中同一标准答案。

### 7.5 `faq_metrics_daily`

| 字段 | 类型 | 说明 |
|---|---|---|
| day | TEXT | `YYYY-MM-DD` |
| eligible_questions | INTEGER | 可进入 FAQ 判断的问题数 |
| rag_answers | INTEGER | 实际调用 RAG 生成的回答数 |
| direct_hits | INTEGER | FAQ 直接回复数 |
| promotions | INTEGER | 当日自动启用数 |
| refreshes | INTEGER | 当日因资料更新而重建数 |
| rejected_answers | INTEGER | 因资料不足或安全检查被拒绝的候选数 |

该表只保存聚合计数，不保存问题、答案或员工身份。FAQ 命中率以 `direct_hits / eligible_questions` 计算。

## 8. 生成、启用与更新规则

### 8.1 首次启用

1. 第 1、2 次命中同一意图：执行普通 RAG，保存匿名观察及最近安全答案。
2. 最近 15 天累计达到第 3 次：本次仍执行普通 RAG。
3. 本次回答通过证据充分性和输出安全检查后，原子创建 `faq_entries` 并设为 `enabled`。
4. 第 4 次开始可直接回复。

### 8.2 资料更新

文档实际新增、修改或删除时，`knowledge_state.revision` 递增。FAQ 查询发现版本不一致后：

1. 将旧 FAQ 视为 `stale`，禁止直接发送旧答案；
2. 本次问题执行普通 RAG；
3. 如果新回答安全且证据充分，立即覆盖原 FAQ 并更新版本，无需重新累计 3 次；
4. 如果新资料不足，则保持失效，不发送旧答案。

这保证已验证为高频的问题在资料更新后只需 1 次提问即可自动刷新，同时不会继续发送过期答案。

同步和本地索引中，文档变更、失效文档删除和 `revision` 递增必须属于同一 SQLite 提交。禁止逐篇提交文档、在整个同步结束后单独递增版本。

同一提交必须将低于新版本的 `enabled` FAQ 标记为 `stale` 并记录失效指标。对本地目录索引，成功快照后必须清理本次目录中已删除的本地文件；该目录是此索引任务唯一管理的本地资料集合。

### 8.3 不能缓存的回答

以下结果不得进入 FAQ：

- `INSUFFICIENT_ANSWER` 或知识库无命中；
- `UNSAFE_ANSWER`；
- 模型结构化输出校验失败；
- 包含来源标题、引用编号、URL、IP 地址或凭据；
- DeepSeek、飞书或数据库调用失败；
- 限流提示、系统错误或其他固定运维提示。

## 9. 安全、隐私与权限

- FAQ 记录不保存员工身份、聊天 ID、消息 ID 或会话上下文。
- 写入前发现疑似姓名、工号、手机号、邮箱或其他个人标识的问题时，不保存问题、别名或答案到 FAQ；该问题仍可走普通 RAG。
- 直接回复仍经过现有 `_clean_answer` 安全检查。
- FAQ 命中仍计入分钟/日限流。
- `RetrievalScope` 生成独立 `scope_key` 并参与缓存隔离。未来收紧权限时，不同范围不能共享答案。
- 日志只记录哈希化 `intent_key`、命中状态、版本和耗时，不记录完整问题或完整答案。
- 统计命令默认不输出标准答案正文。

## 10. 并发与事务

- 观察次数使用 SQLite 原子 UPSERT。
- 第 3 次并发触发时，通过 `(scope_key, intent_key)` 唯一约束和事务保证只生成一条有效 FAQ。
- 同一问题的并发缓存未命中可以分别完成员工本次 RAG 回答，但只有一个工作器能通过唯一约束创建或刷新 FAQ；其他工作器只能原子累计观察次数，不能产生重复 FAQ 记录。
- FAQ 创建、别名更新和观察累计不在 DeepSeek 网络请求期间持有 SQLite 写锁。
- 生成失败不得留下 `enabled` 的空记录。

## 11. 失败处理

- FAQ 表不可用或迁移失败：服务启动失败关闭，不能静默使用不完整缓存。
- FAQ 查询异常：记录脱敏错误并回退普通 RAG，不影响员工获得答案。
- 知识库同步不完整：回滚本次全部待写入文档和版本，保留当前 `revision`，不误使缓存失效或刷新。
- 标准答案失效后生成失败：继续保持 `stale`，下次问题重试。
- 本地相似度不足或文档特征不一致：回退普通 RAG。

## 12. 统计与运维

新增只读 CLI `scripts/report_faq.py`，至少输出：

- 最近 15 天的热门意图数量；
- 启用、失效 FAQ 数量；
- FAQ 直接命中次数和命中率；
- 估算节省的 DeepSeek 生成请求数；
- 因知识库更新而失效/刷新的数量。

报表 CLI 必须使用 SQLite 只读连接，不能执行迁移、建表、FTS 重建或任何写操作。

新增维护 CLI `scripts/cleanup_faq.py`，清理 15 天前的观察桶和长期失效记录。命令不得删除已启用且当前有效的 FAQ。

## 13. 配置

新增环境变量：

```dotenv
RAG_FAQ_ENABLED=true
RAG_FAQ_PROMOTION_COUNT=3
RAG_FAQ_WINDOW_DAYS=15
RAG_FAQ_MIN_TEXT_SIMILARITY=0.82
RAG_FAQ_MIN_SOURCE_OVERLAP=0.80
```

默认值采用本规格已批准参数。设置 `RAG_FAQ_ENABLED=false` 可立即关闭直接回复，但保留数据以便回滚。

## 14. 测试与验收

必须覆盖：

1. 最近 15 天第 1、2 次走 RAG，第 3 次自动启用，第 4 次不调用 DeepSeek。
2. 超过 15 天的历史次数不参与晋级。
3. “供应商开发流程”和“新供应商怎么导入”归入同一意图。
4. 文本相似但核心文档不同的问题不能共享答案。
5. 文档无变化的重复同步不递增知识库版本。
6. 文档新增、修改或删除后 FAQ 立即失效。
7. 已有高频 FAQ 在新版本首次提问后自动刷新，无需再次累计 3 次。
8. 同步失败和部分分页不能递增知识库版本，也不能留下本次同步的部分文档写入。
9. 资料不足、危险内容、来源信息和错误回答不能缓存。
10. 缓存命中仍受限流控制，且不记录员工身份。
11. 多工作器并发达到阈值时只创建一条 FAQ。
12. 从当前生产 v0.2.3 或本地 v0.4.0 数据库自动迁移后，现有文档、消息去重、Token 用量和限流数据保持不变。
13. 关闭 `RAG_FAQ_ENABLED` 后完整回退普通 RAG。
14. 完整测试套件、编译、Compose 配置和敏感信息扫描全部通过。

## 15. 发布与回滚

### 发布

1. 版本号升级为 v0.5.0；
2. 验证从生产 v0.2.3 数据库跨版本迁移到 v0.5.0，并备份生产 SQLite 数据库；
3. 同时更新 `rag` 和 `rag-events`；
4. 执行三个知识空间完整同步；
5. 验证第 3 次晋级、第 4 次直发、知识更新失效和统计命令；
6. 提交 Git 并创建本地 `v0.5.0` 标签，远程推送和生产部署分别执行。

### 回滚

- 首选将 `RAG_FAQ_ENABLED=false`，不需要修改数据库即可恢复普通 RAG。
- 代码回滚到 v0.4.0 时，新增 FAQ 表由旧版本忽略。
- 不直接删除 FAQ 表，避免再次升级时丢失统计基线。

## 16. 成功标准

- 高频问题第 4 次起不产生 DeepSeek 生成请求。
- 同义问题命中正确标准答案，没有跨制度误复用。
- 资料更新后旧答案不会再次发送。
- 缓存路径不降低现有安全、限流、权限和去重保证。
- 生产部署后固定采购、财务、行政问题及新增 FAQ 回归用例全部通过。
