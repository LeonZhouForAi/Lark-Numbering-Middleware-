# v0.3.0 索引生命周期与质量门禁设计

## 背景

v0.2.4 已解决切片丢字、安全默认值、SQLite 并发和静默降级。v0.3.0 聚焦“资料是否完整、是否仍然有效、能否自动验证”：飞书删除或撤权的文档必须退出索引；父页面正文、DOCX 表格和混合 PDF 扫描页必须可检索；质量验收不能只判断“有回答”。

用户已授权连续完成 v0.3.0 和 v0.4.0，中间无需再次确认。本版只开发、测试和提交 Git，不直接部署 Ubuntu 生产环境。

## 方案比较

### 方案 A：完整快照成功后按空间对账（采用）

每次完整遍历一个飞书空间时收集本轮有效 `source_id`。只有列表、分页、下载、解析和索引全部成功后，才删除该空间中未出现的旧索引。优点是无需新表，删除权限边界清楚；缺点是同步仍是全量遍历。

### 方案 B：为文档增加 active/last_seen 字段

先标记、再延迟清理，审计更丰富，但需要数据库迁移和两阶段任务。当前只有三个小型空间，复杂度不划算，留待需要审计保留期时再做。

### 方案 C：只增量 upsert，不删除

风险最低但无法满足制度撤回和权限回收，旧制度仍会回答，因此不采用。

## 设计

### 1. 受限的空间级清理

`IndexStore` 新增：

```python
prune_documents(source_prefix: str, retained_source_ids: Collection[str]) -> int
```

- `source_prefix` 必须非空。
- 所有 retained ID 必须以该前缀开头，否则拒绝执行。
- 单事务删除 stale 文档对应的 FTS 行和 documents；chunks 由外键级联删除。
- 只允许调用方传入 `feishu:{space_id}:`，不能影响其他空间或本地文件。
- 重复执行必须幂等。

`SyncResult` 增加 `deleted: int = 0`。

### 2. 完整快照才有删除权

- 遍历过程中收集 `retained_source_ids`，未变化文档也必须加入。
- 父节点有子页面时，把父 token 加入待遍历队列，但继续处理父页面自身的 DOCX/file 正文。
- 只有全部分页和子树成功结束后才调用 prune。
- 任一列表、下载、正文读取或解析异常都让同步失败，不执行 prune。
- `has_more=true` 时缺少新 page token，或 token 重复，视为不完整快照并抛出 `FeishuSyncError`。
- 当前存在但已变为不支持格式或正文为空的节点不进入 retained；成功对账后清理其旧索引。

### 3. DOCX 可见内容按顺序提取

依赖下限提升到 `python-docx>=1.2`，使用 `Document.iter_inner_content()` 按真实顺序遍历 Paragraph 和 Table：

- 非空段落原样保留。
- 表格每个非空行转换为 `单元格1 | 单元格2`。
- 单元格内部多个段落用空格合并。
- 空行忽略。
- v0.3.0 不解释复杂合并单元格和嵌套表格语义，只保证可见文本不丢失并可检索。

### 4. 混合 PDF 按页 OCR

- 每页先尝试 pypdf 原生文本。
- 只有该页无原生文本且 OCR 开启时，调用 `_ocr_pdf_page(path, page_number)`。
- `pdf2image` 只渲染目标页，设置 `first_page` 和 `last_page`，避免一次加载整份 PDF。
- 原生文本页绝不重复 OCR。
- OCR 依赖、渲染或中英文识别全部失败时抛出 `DocumentExtractionError`，防止残缺结果覆盖旧索引。
- OCR 关闭时允许跳过扫描页。
- 本版不处理“同一页少量原生字 + 大片扫描正文”的双通道合并。

### 5. 金标质量门禁

新增 `eval/golden_questions.json` 和评估模块。数据集只保存问题、标题/来源期望和关键词，不保存制度答案正文。

每个用例字段：

- `id`、`category`、`question`、`answerable`
- `expected_titles`、`expected_source_ids`
- `forbidden_titles`、`expected_terms`、`forbidden_terms`

自动指标：

- Hit@K 和 MRR。
- answerable 问题误判资料不足率。
- unanswerable 问题误答率。
- 禁止标题命中率。
- 员工可见回答来源泄漏率。

CLI 支持 `--cases`、`--retrieval-only` 和阈值参数；报告只输出指标，不输出答案正文和切片内容。阈值失败时退出码非 0。

仓库提供 30 条不含制度正文的初始用例：三部门正式问题、口语改写、无答案、错部门、冲突版本和提示注入类别。业务负责人上线前仍需核对预期标题是否对应当前正式制度。

### 6. 版本与重建

- 项目版本升级到 `0.3.0`。
- 切片策略升级到 `hybrid-v4`，强制现有附件重新解析，使 DOCX 表格和逐页 OCR 修复进入索引。
- CHANGELOG、README 和 `.env.example` 同步更新。

## 测试与验收

1. Store：只清理指定空间 stale 文档，保留 retained、其他空间和本地文档；FTS 同步；越界输入拒绝；幂等。
2. Sync：删除节点后清理；未变化文档保留；分页异常不清理；父页面正文和子页面同时入库。
3. DOCX：表格-only、段落-表格-段落顺序、空行、表格关键词检索。
4. PDF：文本页不 OCR、扫描页只 OCR 对应页、混合页序正确、OCR 关闭、OCR 异常显式失败。
5. Eval：Schema、重复 ID、Hit@K/MRR、无答案、禁止标题、来源泄漏和报告脱敏。
6. 全部 pytest、compileall、Compose config、diff check 和密钥扫描通过。

## 非目标

- 不增加向量数据库、Embedding 或外部重排序服务。
- 不增加用户/部门 ACL。
- 不自动部署生产环境。
- 不提交公司制度正文或真实答案到 Git。
- 不在同步失败时清理任何旧索引。

## 回滚

代码可回滚到 v0.2.4。`prune_documents` 不改变数据库结构；生产部署前必须备份 SQLite。`hybrid-v4` 仅改变缓存签名。若 v0.3.0 同步失败，保留旧数据库并恢复 v0.2.4 容器即可。
