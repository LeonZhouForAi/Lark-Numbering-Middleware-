# DeepSeek 混合语义切片设计

## 目标

在保留原始制度正文、现有 OCR、自动同步和消息去重能力的前提下，引入 DeepSeek 对本地初步切片进行语义合并与拆分，提高财务、采购和行政人事问题的检索命中质量。

员工可见回答不展示“来源”区块或 `[1]`、`[2]` 等引用编号；后台继续保留引用信息用于排查。

## 范围与约束

- 三个知识库的正文会在索引阶段发送给公司配置的 DeepSeek API。
- DeepSeek 不得改写制度正文，只能返回原始段落编号的分组方案及检索元数据。
- 模型生成的标题、关键词和摘要只参与检索，不作为回答依据。
- DeepSeek 不可用时必须回退到本地切片，不能中断知识库同步。
- 文档未变化时不得重复调用 DeepSeek。

## 处理流程

1. 从飞书递归同步在线文档和附件。
2. PDF 在服务器本地解析；扫描件使用本地 Tesseract OCR。
3. 按标题、页码、段落、列表和表格边界生成带稳定编号的原子段落。
4. 将原子段落按批次发送给 `deepseek-v4-flash`。
5. 要求 DeepSeek 使用 JSON 输出，返回：
   - 每个语义块包含的连续段落编号；
   - 语义标题；
   - 关键词列表；
   - 一句检索摘要。
6. 程序校验编号连续、无遗漏、无重复后，根据编号从原始段落重新组装正文。
7. 正文写入 `content`，模型生成的标题、关键词和摘要写入独立的 `search_text`。
8. 查询时同时匹配原始正文、文档标题和 `search_text`；生成回答时只把原始正文发送给 DeepSeek。

## 数据模型

`chunks` 表新增 `search_text` 字段，默认空字符串。已有数据库启动时自动迁移。

每个切片保存：

- `content`：由原始段落拼接的制度原文；
- `title`：原文文档标题；
- `search_text`：语义标题、关键词和摘要；
- `page` / `section`：现有定位信息；
- 稳定切片 ID：由来源 ID、原始正文和切片序号生成。

`documents.checksum` 继续标识文档内容。另将切片策略版本和模型名称纳入索引签名；正文或策略变化时才重新切片。

## DeepSeek 调用协议

- 默认使用 `DEEPSEEK_CHUNK_MODEL=deepseek-v4-flash`。
- 使用 `/chat/completions` JSON 输出。
- 单批输入默认不超过 12,000 个字符，避免单次请求过大。
- 温度使用低值，保证分组稳定。
- 输出只能引用输入段落编号，不接受模型返回的改写正文。
- API Key、文档正文和模型响应不写入应用日志。

## 检索规则

保留当前本地 SQLite 检索，不新增向量数据库。

评分顺序：

1. 文档标题命中权重最高；
2. 原始正文命中；
3. `search_text` 中的标题、关键词和摘要作为补充召回信号。

模型生成元数据只能帮助找到原文，不能直接进入最终回答上下文。

## 缓存与同步

- 飞书附件校验和未变化时跳过下载后的解析和 DeepSeek 切片。
- 在线文档原始内容校验和未变化时跳过 DeepSeek 切片。
- 每小时定时同步保持不变。
- 切片策略版本变化时允许一次性重新生成全部索引。

## 失败回退

以下情况自动使用现有本地切片：

- DeepSeek 超时、限流或服务错误；
- JSON 无法解析；
- 段落编号遗漏、重复、越界或不连续；
- 返回空分组；
- 单个语义块超出本地最大长度限制。

失败只记录错误类型和来源 ID，不记录正文、API Key 或模型原始响应。

## 员工可见回答

- 回答正文不再拼接“来源”列表。
- 提示词禁止输出 `[1]` 等引用编号或来源说明。
- 后台 `RagAnswer.citations` 继续保留，供故障排查。

## 测试与验收

### 单元测试

- DeepSeek 返回合法分组时，切片正文与原始段落逐字一致。
- 编号遗漏、重复、越界时回退到本地切片。
- 相同校验和不重复调用 DeepSeek。
- `search_text` 参与检索，但不进入回答上下文。
- 回答文本不包含“来源：”或引用编号。
- 后台 citations 仍存在。

### 线上验收

分别使用财务、采购、行政人事问题对比旧切片与混合切片：

- 财务报销流程是什么；
- 供应商管理程序是什么；
- 员工入职流程是什么。

新切片至少保持三类问题均可命中，并检查回答依据来自原始正文。若 DeepSeek 切片失败，线上回答仍须由本地切片正常提供。

## 非目标

- 本阶段不引入向量数据库或新的 Embedding API。
- 不让 DeepSeek改写、补充或纠正制度正文。
- 不改变飞书机器人可用范围、知识库权限和同步周期。
- 不删除后台引用和审计能力。
