# v0.5.1 FAQ 极速预热实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 在每个知识空间同步成功后，从最新版资料中筛选最多 10 个高价值候选，后台生成并直接启用 FAQ，使员工首次命中即可本地直发答案。

**架构：** 同步原子提交后向 SQLite 预热作业表入队。预热 worker 以 2 个并行任务按本地规则筛选候选，再使用 DeepSeek 结构化生成标准问题、同义问法和答案；通过现有版本、权限、个人标识和输出安全检查后，写为 `preheated` FAQ。员工问答复用 v0.5.0 的 `FaqService` 匹配和版本栅栏，不在消息处理线程调用预热模型。

**技术栈：** Python 3.14、SQLite WAL、现有 DeepSeek OpenAI 兼容客户端、飞书同步、pytest、systemd/Docker Compose。

- [ ] **步骤 3：实现入队、领取和版本栅栏**

完整成功同步的 `apply_document_snapshot()` 在同一版本提交后插入 `(space_id, revision)` 作业；不在同步失败或资料未变时入队。实现：

实现以下明确 API：

- `claim_preheat_job(*, now: float | None = None) -> PreheatJob | None`：原子领取最早的 queued 作业，过期 running 作业按重试规则重新入队。
- `complete_preheat_job(job_id: str, *, generated: int, failed: int) -> None`：只完成当前运行作业并写入计数。
- `fail_preheat_job(job_id: str) -> None`：重试次数未达上限时回到 queued，达到上限时标记 failed。

领取使用状态租约，重复 worker 只能领取一条。若 job 版本不等于当前 `knowledge_revision`，将其完成但不生成候选。
