# v0.4 回滚到 v0.3 操作手册

## 适用范围

本手册只用于把“瀚邦为知识库助手”从 v0.4 回滚到 v0.3。v0.4 将 `chunks_fts` 改为四列预分词结构，v0.3 仍按三列结构写入；直接切换旧代码会导致同步写入失败。

脚本只处理这一处不兼容结构。`documents.space_id`、消息状态字段和治理表会保留，v0.3 会忽略它们。

## 前置条件

1. 确认当前数据库文件和目标备份目录的绝对路径。
2. 停止 `rag`、`rag-events` 和所有同步任务。执行期间不能有 v0.4 进程访问数据库。
3. 在受控磁盘上准备仅管理员可访问的备份目录。
4. 不要手工复制正在使用 WAL 的 SQLite 主文件；必须使用脚本调用 SQLite Backup API。

## 操作步骤

```bash
cd /opt/data-assistant/feishu-rag
sudo systemctl stop feishu-rag-sync.timer
sudo docker compose stop rag rag-events
mkdir -p data/backups

# 只读预检
python scripts/prepare_v03_rollback.py data/rag.sqlite3 \
  --backup data/backups/rag-before-v03.sqlite3

# 显式执行
python scripts/prepare_v03_rollback.py data/rag.sqlite3 \
  --backup data/backups/rag-before-v03.sqlite3 --execute
```

只读预检应输出 `status=ready`，且不会创建备份或修改数据库。显式执行按以下顺序完成：

1. 校验源数据库完整性和 FTS v2 精确列签名；
2. 取得 `BEGIN IMMEDIATE` 写互斥，并持续持有到结构切换提交；
3. 在写互斥窗口内，以独占文件名创建权限受限的 SQLite 一致性备份；
4. 再次校验备份完整性及 FTS v2，然后删除源库 `chunks_fts`；
5. 确认 `documents/chunks` 行数未变化后提交并释放写互斥。

任何已有备份、未知 FTS 结构、损坏数据库或不存在的备份目录都会使脚本失败关闭。脚本不提供覆盖或强制参数。

## 切换与验收

脚本成功后再切换到 v0.3 代码或镜像。v0.3 首次打开数据库会创建：

```sql
chunks_fts(chunk_id UNINDEXED, title, content)
```

依次检查：

1. v0.3 服务可以启动；
2. 现有制度问答仍可通过字面检索命中；
3. 新文档可以同步写入；
4. 运行一次三个空间的全量同步，以完整回填旧 FTS；
5. 健康检查和固定三部门问题全部通过后，再恢复同步定时器。

## 恢复 v0.4 数据库

如果回滚准备或 v0.3 验收失败，保持所有服务停止。保留失败现场数据库，复制留档后，用脚本生成的备份恢复原数据库文件，再启动 v0.4。恢复前后都应执行 SQLite 完整性检查，且不得覆盖唯一备份。
